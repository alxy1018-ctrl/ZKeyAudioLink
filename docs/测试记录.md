### 3.4 真实 Z 播放 / 停止 / 重播 + CABLE 输出验证

目的：不用离线渲染，而是让**真实发布包 + 真实全局 Z + 真实 CABLE**跑一遍，并从 CABLE Output 录制发送流。

测试素材：6 秒 WAV，前 1 秒静音，后 5 秒 1 kHz / 0.2 幅度；保存起点 1.000 s。为隔离变量，本轮把麦克风增益和本地监听音量调为 0，只保留素材发送。

时间线：

```text
18:16:08.601  Z 第一次：material started generation=1
18:16:11.677  Z 第二次：material stopping generation=1；11.708 completed reason=UserStopped
18:16:12.793  Z 第三次：material started generation=2
18:16:17.794  generation=2 completed reason=EndOfStream（自然结束）
```

同时用 Doctor 从 CABLE Output 录 16 秒（18:16:02–18:16:18），按 0.5 秒窗口分析：

| 窗口 | RMS | 峰值 | 说明 |
| --- | --- | --- | --- |
| 0–6.0 s | ~0.00000 | 0 | Z 之前，无素材 |
| 6.0–6.5 s | 0.07000 | 0.2000 | Z 起播后的第一个窗口（含淡入） |
| 6.5–9.0 s | **0.14140** | **0.2000** | 1 kHz 素材，RMS 理论值 0.2/√2 |
| 9.5–10.5 s | 0.00000 | 0 | 第二次 Z 停止后的静音 |
| 10.5–16.0 s | **0.14140** | **0.2000** | 第三次 Z 重播，持续到采集结束 |

结论：

- 真实 Z 起播、停止、再次起播都生效；停止后 CABLE 输出确实静音，重播从保存起点重新开始。
- 素材以 0.2 幅度、1 kHz 进入 CABLE Input，并从 CABLE Output 原样被测到；说明“应用混音 → 虚拟声卡 → 通话软件可读的录音端”链路在真实设备上成立。
- 自然结束时应用日志为 `EndOfStream`，符合设计。

### 3.5 长按与最小化验证

- 应用最小化到任务栏后，在 3 秒长按 Z：日志只在 18:17:41.261 出现一次 `material started generation=4`，长按期间没有额外的 stop/start；说明自动重复被抑制。
- 应用最小化时 Z 仍然被接收，说明 `RIDEV_INPUTSINK` 的后台接收路径实际工作。
- 本机没有第二个可安全占用的编辑器窗口做“原窗口收到 z”的逐字验证；按键不被 Raw Input 吞掉是设计属性，但仍建议在记事本/浏览器里人工确认一次。

## 4. 离线混音验证

目的：在没有 CABLE 的情况下，验证“起点 → 结尾”的实际混音输出，而不是只看代码。

输入：人工生成的 3 秒 WAV，前 1 秒静音，后 2 秒 440 Hz / 0.3 幅度；`--mic-tone` 打开一路 440 Hz / 0.1 幅度测试人声。

```powershell
dotnet ...\ZKeyAudioLink.Doctor.dll render --in artifacts\doctor-input.wav --offset 00:01.000 --out artifacts\doctor --mic-tone
```

结果：

```text
reason:  EndOfStream
send:    artifacts\doctor\send.wav (96000 frames, 2.00 s)
monitor: artifacts\doctor\monitor.wav (96000 frames)
render:  590 ms wall clock
```

输出分析：

| 流 | 帧数 | 时长 | RMS | 峰值 |
| --- | --- | --- | --- | --- |
| send.wav | 96000 | 2.00 s | 0.2817 | 0.4000 |
| monitor.wav | 96000 | 2.00 s | 0.1689 | 0.2400 |

结论：

- 从 1.000 s 起点渲染出了 2.00 s，帧数精确等于输入剩余时长。
- monitor 峰值 0.24 = 素材 0.3 × 监听增益 0.8；send 峰值 0.4 ≈ 素材 0.3 + 测试人声 0.1；监听流没有人声。
- 这是离线、无设备抖动的验证，不等于真实 WASAPI 双设备时钟与延迟验证。

## 8. 结论与待办

可以确认：

- 音频数学、缓冲、状态机、配置/媒体库的离线行为有自动化测试（58 个）。
- 自包含程序在无系统 .NET 的机器启动；真实 WASAPI 监听、麦克风、CABLE Input/Output 均能打开。
- 真实全局 Z 能起播、停止、再次起播；素材以正确幅度进入 CABLE Output；监听音量 0 不影响发送；3 秒长按只触发一次。
- 缺 CABLE 时按设计降级，不崩溃。

不能确认：

- QQ 对端能否同时听到素材和人声（OOPZ 已有用户实测音质反馈，见 A08）。
- 真实耳机监听（本机耳机端点未连接，当前监听输出是 Realtek 扬声器）。
- 真实麦克风人声在 CABLE 中的持续、自然结束后重播、切歌/改起点、热插拔、60 分钟稳定性。
- 全局 Z 在输入法、游戏、管理员窗口中的实际行为，以及原窗口字符透传。
