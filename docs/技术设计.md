# 技术设计

## 1. 目标数据流

```text
真实麦克风 ──捕获──格式转换/有界队列──→ 麦克风环形缓冲 ─┐
                                                        ├─ 混音/限幅 → 发送环形缓冲 → CABLE Input
选中素材 ──解码/定位/重采样──→ 素材环形缓冲 ────────────┘                         ↓
                                └─ 监听环形缓冲 → 实体耳机                  CABLE Output → QQ / OOPZ
```

- 发送流 = 麦克风 + 素材；监听流 = 只有素材。
- 麦克风路径从引擎启动起持续运行，停止素材只停止素材声部。
- 不捕获系统回放，不启用 Windows“侦听此设备”，不改默认设备。

## 2. 技术栈

- C# / .NET 10（LTS）/ WPF，`net10.0-windows`，`win-x64`。
- NAudio 3.3.0：`WasapiPlayer`、`WasapiRecorder`、`AudioFileReader`、`WdlResamplingSampleProvider`。
- 输出和采集都用 WASAPI shared mode + 事件同步；共享模式下由音频引擎完成设备格式转换。
- 内部统一工作格式：**48 kHz / 32-bit float / 立体声**。
- 自包含发布，不裁剪，不自包含单文件。

## 3. 模块

| 模块 | 职责 |
| --- | --- |
| `AudioEngine` | 设备生命周期、三路设备的打开/重建、素材播放入口、故障降级 |
| `DeviceService` | 枚举 endpoint、按 endpoint ID 查找、订阅设备增删/状态变化 |
| `CaptureService` | WASAPI 麦克风采集；回调只复制入队，独立线程转 float 写环形缓冲 |
| `FileMaterialSource` | 单解码线程：AudioFileReader → 定位 → 声道映射 → WDL 重采样 → 48k 环形缓冲 |
| `MixEngine` | 单混音线程；发送环为主时钟；起播/停止/EOF/淡入淡出；generation；指标 |
| `MixProcessor` | 纯函数式混音：麦克风/素材增益、包络、限幅、峰值电平 |
| `RenderSink` | 一路 WASAPI 输出 + 有界环 + 漂移丢补帧；一直提供数据（空时补静音） |
| `PlaybackController` | 串行化切换命令；Idle/Preparing/Playing；取消与 generation |
| `MediaLibrary` | 导入复制、SHA-256 去重、时长校验、删除副本、起点校验 |
| `SettingsStore` | JSON 配置、临时文件 + 原子替换、损坏备份与恢复 |
| `RawInputHotkeyService` | Raw Input `RIDEV_INPUTSINK` 后台播放快捷键；去重；不吞键 |
| `MainViewModel` | 状态呈现、设备下拉、电平、音量、导入/删除、托盘提示 |
| `Doctor` | 设备枚举、离线渲染、CABLE 回路自测 |

## 4. 线程与缓冲

常量见 `AudioConstants.cs`：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| 采样率 / 声道 | 48000 / 2 | 内部工作格式 |
| `BlockFrames` | 480 | 10 ms 混音块 |
| `FadeFrames` | 720 | 15 ms 淡入/淡出 |
| `SendTargetFrames` | 2400 | 发送环目标 50 ms |
| `SinkCapacityFrames` | 12000 | 每路输出环上限 250 ms |
| `MicRingCapacityFrames` | 48000 | 麦克风环 1 s |
| `MaterialRingCapacityFrames` | 96000 | 素材环 2 s |
| `PrefillFrames` | 5760 | 起播前预读 120 ms |

线程：

1. **WASAPI 采集回调**：只把 `ReadOnlySpan<byte>` 复制到有界队列；不写盘、不改 UI、不等待锁、不解码。
2. **MicPump**：从队列取包，转 48k float 立体声（正常路径直接复制，回退路径才用转换器），写入麦克风环。
3. **Decoder**：单个解码线程，从保存起点读取文件，重采样到 48k，写入素材环；环满时等待，取消时退出。
4. **Mix**：单线程；按发送环深度生成 10 ms 块；从麦克风环和素材环读取；混音后写两路输出环；处理淡入淡出、EOF、停止、指标。
5. **WASAPI 播放线程**（每路一个）：由 `WasapiPlayer` 驱动，从各自输出环拉数据；环空时补静音，永不返回 0，因此播放器不会把“暂时没数据”当成 EOF。

所有跨线程队列/环都是有界的；素材预读 2 s，麦克风 1 s，输出 250 ms。

## 5. 起播、停止与 EOF

- `PlaybackController` 在 `Idle` 上收到全局快捷键：generation++，进入 `Preparing`，异步创建 `FileMaterialSource` 并预读 120 ms。
- 预读完成后向 `MixEngine` 投递 `Start(generation, source, offset)`；混音线程把该素材设为当前声部，15 ms 淡入。
- `Playing` 中再按快捷键：控制器进入 `Idle`，`MixEngine` 在 15 ms 内淡出素材，清空素材声部；麦克风继续。
- 解码线程读到 EOF 后设置 `EndOfStream`；混音线程在素材环剩余 ≤ 一个块 + 淡出长度时开始最后一个淡出，排空后发 `MaterialCompletion(EndOfStream, generation)`。
- 旧 generation 的回调由控制器忽略；控制器在准备中再次按快捷键会取消 CTS 并清理，避免“已取消的播放又启动”。
- 停止只清素材声部，不清包含人声的总混音链路。

## 6. 两路输出与漂移

- **发送路是主时钟**：混音线程只在发送环低于 50 ms 时生成数据，因此整体时间轴跟随虚拟声卡设备时钟。
- 监听路从同一个混音块获得素材；监听环深度偏离时，由 `RenderSink` 做极小校正：
  - 深度 > 100 ms（监听）/ 150 ms（发送）：丢弃最旧一帧；
  - 深度 < 20 ms（监听）/ 10 ms（发送）且已有历史帧：重复上一帧一帧；
  - 空环：补静音并计数欠载。
- 单帧校正只在深度真正偏离时触发；插入一帧后深度上升，分支自然停止，避免持续重复。更长的连续性漂移应看日志中的 `ClockCorrections` / `UnderrunFrames`。
- 两路不共享可变 reader：只有一个解码生产者，素材数据复制到两路独立环。

## 7. 状态机

| 当前状态 | 事件 | 行为 |
| --- | --- | --- |
| Idle | 快捷键，选中有效 | Preparing，预读后 Playing |
| Preparing | 快捷键 | 取消 CTS，回 Idle，丢弃已准备的素材 |
| Playing | 快捷键 | 停止素材，回 Idle；麦克风继续 |
| Playing | EOF + 排空 | Idle，保留起点 |
| Preparing/Playing | 换曲 / 改起点 / 删除当前曲 | 先停止/取消，下一次快捷键才播放新选择 |
| 任意 | 解码失败 | 停止素材，报错，保留麦克风 |
| 任意 | 必需设备故障 | Degraded，停止素材，提示通话风险 |
| Idle | 未选文件按快捷键 | 轻提示，不改变音频链路 |

## 8. 设备生命周期

- 保存 endpoint ID，不只保存显示名；设备列表按 ID 匹配。
- 启动时：读取保存 ID；首次运行没有 ID 时选默认麦克风 / 默认播放；虚拟发送端只自动选检测到的 CABLE Input，若没有则保持未选并降级，不随便拿一个播放设备冒充虚拟线。
- 设备增删/状态变化：刷新列表并检查已选 ID；缺失时标记 Degraded、停止素材、提示重连；**不自动改用另一支麦克风或其他播放设备**。
- `ApplyDevicesAsync`：停止素材 → 停止采集/混音/两路输出 → 更新设置 → 重新打开；失败给出具体错误。
- 虚拟发送端缺失：不启动混音（没有可写目标），状态 Degraded，界面禁用播放。
- 耳机输出缺失：允许麦克风继续转发，但阻止素材播放（避免只有对方听到素材）。
- 麦克风缺失：允许素材播放，状态 Degraded，提示对方只能听到素材。
- 退出：按 混音 → 采集 → 两路输出 → 设备服务的顺序释放；解码源由专用清理线程串行 Dispose，避免在 ThreadPool/Mix 线程里 Join 解码线程。

## 9. 全局播放快捷键

- 默认 Z；`AppSettings.HotkeyKey` 保存 `HotkeyKeys` 里的稳定名称（A–Z、0–9、F1–F12、常用控制键、主键盘标点）。只支持主键盘区单键，不支持组合键、鼠标侧键、媒体键、小键盘、Win/CapsLock/PrintScreen。
- 使用 Raw Input，而不是会吞键的 `WH_KEYBOARD_LL`：`RIDEV_INPUTSINK` 后台接收，原窗口仍收到按键。
- 消息窗口挂在 WPF UI 线程，`WM_INPUT` 中解析 `RAWKEYBOARD`；按 VKey 匹配，字母/数字/标点额外保留扫描码兜底（输入法把 VKey 变成 `VK_PROCESSKEY` 时仍能匹配），E0 扫描码不参与字母兜底。
- 去重：按设备句柄维护“选定键按住”集合；集合为空时的第一次 down 才切换；up 移除；设备变化、睡眠恢复、会话切换清空。换键时也清空按住状态。
- 选择新键立即更新 `HotkeyState` 并写入配置，不重新注册 Raw Input；关闭开关时注销 Raw Input，并清空状态。
- `Shift/Ctrl/Alt` 不影响匹配；已知不支持：锁屏、UAC 安全桌面、管理员窗口、部分游戏输入保护；不尝试绕过。

## 10. 配置与媒体库

- 根目录：`%LOCALAPPDATA%\ZKeyAudioLink`。
  - `settings.json`、`settings.json.bak`、`Media\`、`Logs\`。
  - 配置包含设备 ID、音量、`hotkeyEnabled`、`hotkeyKey`、媒体条目和起点；旧配置没有 `hotkeyKey` 时默认 Z。
  - 如果该目录不可写（策略/安全软件），依次回退到程序目录 `Data\`、临时目录；启动日志记录实际根目录。
- 保存：序列化到同目录 `.tmp` → `File.Replace`（首次则 Move）→ 保留 `.bak`；失败会记录并保证导入回滚。
- 损坏：把原文件改名为 `settings.json.corrupt-时间戳`，尝试 `.bak`，仍失败则用默认值并提示。
- 媒体：导入时复制到 `Media\{guid}{ext}`；用 SHA-256 去重；删除只删应用副本；原文件不变。中文/空格路径由 .NET 文件 API 直接支持。
- 不记录用户键盘内容，不录制通话；日志只写固定事件和性能计数。

## 11. 已知保留的工程选择

- 输出环 250 ms 上限偏大，是为了容忍系统卡顿；正常目标是 50 ms。
- 监听端单帧丢补属于工程折中：比几十毫秒的断续更不容易被察觉；若真实设备长期漂移，应优先检查设备和采样率，而不是无限加大环。
- 起播前预读 120 ms 会带来少量内存（约 46 KB/声道）换稳定起播。
- 耳机监听音量、发送音量、麦克风增益都在混音器内做平滑，不依赖设备音量。
- 不启用 Windows “侦听此设备”，也不捕获通话输出，以避免双重路由和回声。
